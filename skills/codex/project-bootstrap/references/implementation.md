# Implement the architectural delta

Work inside the confirmed target and scope. Before the first write or dependency
setup, check that consequential choices have support from user decisions, applicable
project contracts or scoped delegation. Stop for missing answers instead of encoding
an unconfirmed approach in setup files or project instructions.

The reference architecture supplies roles and dependency rules; native tooling and
actual requirements determine the files that implement them. Do not turn every
illustrated layer into a mandatory directory or every template into a document.

## New scaffold

1. Establish native runtime/package configuration and dependency declarations.
   Respect project constraints and lockfile/package-manager conventions; inspect
   scaffolder/install commands and their effects before using them.
2. Implement the smallest real entrypoint and composition/configuration path for
   the selected app, CLI or library. Connect actual dependencies; an empty main
   function, static directory tree or always-successful task is not a runnable scaffold.
3. Place real responsibilities in their selected owners. Keep business policy out
   of startup/composition and framework/IO details outside any actual core rules.
4. Supply native build/start/import and meaningful smoke-check commands. Use a
   representative request, CLI invocation or public library call to exercise wiring.
5. Derive the quickstart, architecture map and future-AI instructions from the
   implemented files and verified commands.
   Materialize selected language/file/context/privacy choices in project-owned
   configuration or concise policy, and implement the native verification needed
   to support the actual acceptance claims.

A minimal neutral startup route, page or CLI help can establish a working entrypoint.
It does not justify implementing login, checkout, CRUD or another business feature.

## Existing project

1. Capture affected paths/contracts and baseline results. Plan bounded moves or
   extractions with their callers, import/export updates and rollback needs.
2. Introduce the intended public boundary, move/extract code and rewire composition
   in a coherent step. Preserve business behavior, data and unrelated working changes.
3. Update native discovery, configuration, generated sources, build/start tasks and
   tests together. Do not edit generated output instead of its owner.
4. Run relevant checks after a meaningful migration boundary. Fix in-scope regressions
   before continuing. Remove superseded wiring only once the replacement is verified.
5. Update current architecture and commands from actual code. Keep unfinished
   migration progress explicit; documentation changes alone do not finish a refactor.

Resolve newly discovered breaking changes or expanded scope before dependent writes.
Do not reset user edits, move unrelated modules for cosmetic consistency or treat
a generic file-size advisory as permission for repository-wide reorganization.

## Controlled execution and recovery

For multi-step work, retain the current step, permitted writes, baseline, results,
blockers and next action in the project's existing plan/task format. A task handoff
must identify its inputs and checks. Do not launch another phase or delegate work
without authorization under the actual runtime contract.

Keep coupled changes with one owner. Independent work can be batched when its inputs
are stable and writes/resources do not conflict. Worktrees do not resolve conflicting
interfaces. Follow available lifecycle tools instead of inventing unsupported controls.

Use disposable data and task-owned processes for checks. Clean up only those exact
resources; preserve existing user services and live applications. Stop only work
blocked by missing decisions, unsafe effects or required prerequisites. Deployment,
publication, production-data mutation and live application replacement need their
own authorization; ordinary local delivery does not imply them.

## Native engineering baseline

Apply the selected source/file formats, natural-language policies, formatting,
file/context budgets, exceptions and privacy boundaries in their project owners.
Existing native policy takes precedence. Preserve warn/block/off semantics and
distinguish native enforcement from manual inspection or an advisory.
Use compatible project-local runtimes/dependencies rather than changing global tools.

Use the same implemented native commands for humans and agents. Provide suitable
focused/fast/full checks for the selected risk and keep outputs actionable.
Honor protected acceptance expectations and owned files; do not weaken a check
instead of fixing the implementation. Verify selected hook/check protections on a
representative violation and valid case where the runtime supports it.

For multiple environments, implement native configuration selection/validation,
document precedence, separate secrets from public build values and isolate actual
data/resources. Keep one codebase and explicit configuration ownership. Preserve
native deployment/build conventions, use synthetic profiles in tests and separate
file readiness from authorized real deployment.

Use synthetic examples and portable paths. Keep private configuration and diagnostics
outside shared artifacts and actual package inputs. Inspect built members and relevant
source-map/debug/image metadata when those formats are produced; ignore rules alone
do not establish exclusion. Native instructions cannot create permissions the runtime
does not enforce.

## Grounded project materials

Each output must explain an actual runtime, module, interface, dependency, decision
or recurring project task. Name concrete source paths and working commands.
Merge small subjects into the existing owner; do not create duplicate indexes,
custom project manifests, empty reports or a document per hypothetical capability.

Record selected architecture, justified deviations and conditional evolution rules.
For a future module/layer/package change, identify the current extension point,
observable trigger, preserved contracts, staged migration and checks. Conditional
guidance is not implemented code or permission for unrequested future work.

Populate or merge shared project instructions through AGENTS.md, preserving authored
rules and their scope. When the target uses Claude, its CLAUDE.md imports that shared
file and retains only actual Claude-specific additions. Resolve relative imports
from their containing file; preserve existing supported locations and native settings.
Keep shared rules in one owner, repair duplicate/conflicting instructions and verify
the loading mechanism for each selected tool. Point to actual architecture/evolution
and runnable commands; a valid path does not prove native loading.

If native entries are private local outputs, edit their selected internal source and
materialize/check the native files using real project tools. Keep new plans/tasks,
handoffs and archives in the selected record destinations. Public material cannot
reference internal files or require private tooling to build/test/run. Implement and
exercise selected boundary/export commands before claiming this mechanism exists.
All lasting instructions and tools belong to the target project; ordinary development
must not depend on installed skill resources or another skill being present.

Implement a proportionate knowledge entry and runnable source lookup using approved
roots and native tools. Reuse existing navigation; a small README task map can suffice
for public knowledge, while internal routes stay in the private entry.
Keep current authority, active work and historical rationale distinguishable. If a
generated catalog is selected, implement generation and freshness/link checks from
source metadata. Update affected routes and links with document moves/replacements,
then exercise representative task queries against the delivered sources.

Resolve template placeholders, remove irrelevant sections and label missing evidence.
Archive only finished scope while preserving outcomes, ids and working links.
Required code and runtime checks cannot be deferred under a claim of completed delivery.
